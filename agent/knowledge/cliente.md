# Como ler os dados do cliente

Este arquivo explica ao Edu o que existe na pasta `data/` e como interpretar cada informação.
Sem isso, o agente recebe os dados mas não sabe o que eles significam.

> ✍️ **Sua vez:** para cada arquivo em `data/`, descreva o que ele contém e o que cada campo
> significa. Assim o Edu consegue usar os dados como exemplos personalizados nas explicações.
>
> Estrutura sugerida (preencha conforme os seus arquivos reais):

## `perfil_investidor.json`

> ✍️ O que tem aqui? (ex.: nome, objetivos, perfil de risco). O que cada campo quer dizer?

## `transacoes.csv`

> ✍️ O que cada coluna representa? (ex.: data, descrição, valor, categoria). Como o Edu pode usar
> isso para dar exemplos reais do dia a dia do cliente?

## (outros arquivos)

> ✍️ Documente aqui qualquer outro dado que você colocar em `data/`.

---

> 🔒 **Regra de ouro (reforce isso no `AGENTS.md` também):** o Edu só deve usar como verdade o que
> está nestes dados. Se a informação não estiver aqui, ele admite que não sabe. Ele nunca inventa.
